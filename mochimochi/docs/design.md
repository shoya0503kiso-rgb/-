## DB設計（prisma/schema.prisma）

日付はすべて **営業日**（JST、`dayChangeHour` 時より前は前日扱い。初期値 6時）の `YYYY-MM-DD` 文字列。

| テーブル | 内容 | 主な制約 |
|---|---|---|
| `StoreSetting` | 店舗設定1行（店名・ロゴ・音声・各種ポイント量・確率・QR用の値・位置情報） | id = 1 |
| `AdminUser` / `LoginFailure` | スタッフアカウント・ログイン失敗（総当たり対策） | loginId 一意 |
| `Member` | 会員（ニックネーム・LINEユーザーID・ポイント残高・来店回数・スタンプ・累計もち） | lineUserId 一意 |
| `PointTransaction` | ポイント増減の履歴（種類・理由・担当スタッフ）。**残高 = この合計** | |
| `Visit` | 来店（QRチェックイン） | 会員×営業日 一意＝1日1回 |
| `GamePlay` | デイリーゲームの結果 | 会員×営業日 一意＝1日1回 |
| `MochiDaily` | 連打の1日分（タップ数・当選数） | 会員×営業日 一意 |
| `RankTier` | 来店ランク（名前・必要来店回数・色） | |
| `PlacePointRule` | ダーツ／ポーカーの順位ごとのポイント | 種目×順位 一意 |
| `Match` / `MatchEntry` | 大会・ゲーム結果と参加者の順位・付与ポイント | 試合×会員 一意 |
| `SubmarineLog` | サブマリン ＋1／−1 の記録（月で集計） | |
| `PointDay` | ポイント倍率デー（◯倍 or 来店◯pt） | 日付 一意 |
| `Event` | イベント予定 | |
| `Reward` / `Redemption` | 交換メニューと交換チケット（未処理→提供済み／取消） | |

## 不正対策

- **チェックインQR**：`HMAC(SESSION_SECRET, 営業日 + qrSalt)` から作るコード。日付が変わると自動で変わり、前日のQRの写真では使えない。漏れたら管理画面で即作り直し（qrSalt を変更）
- 1日1回はDBの一意制約で保証（同時に押しても二重にならない）
- 位置情報チェック（任意）：お店の緯度経度から指定メートル以内のみ
- ゲーム・連打の抽選はすべてサーバー側（暗号学的乱数）。連打は1秒20回・1回100回までしか受け付けず、1日の当選上限は条件付き更新で超えない
- ポイントは残高がマイナスにならないよう条件付きで減算し、すべて履歴に残す
