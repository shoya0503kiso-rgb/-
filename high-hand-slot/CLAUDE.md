# ハイハンドスロット(9High福山)

ポーカーバー「9High福山」で使う、テレビ演出用のスロットアプリ。
フルハウス以上の役でショーダウン勝ちしたお客さんが、店内テレビに表示されたスロットを回して景品を狙う。

このファイルが唯一の仕様書。迷ったらここに戻ること。仕様にない細部は「店で盛り上がる・スタッフが迷わない」方向で自分で決めてよい。決めたことは `DECISIONS.md` に1行ずつ記録する。

---

## 1. 技術構成

- Node.js(LTS)+ Express + socket.io
- フロントは素の HTML / CSS / JavaScript(ビルド不要)
- データは `data/` 配下の JSON ファイル(DB不要)
- 店のPCで `npm start` 一発で起動し、同じWi-Fi内のテレビ(ブラウザ)とスマホ/タブレットから接続する
- インターネット接続なしで動くこと(外部CDN・外部フォント・外部音源は使わない)
- 効果音は Web Audio API で生成する(音声ファイルを外から持ってこない)
- Windows / Mac どちらでも動くこと

## 2. 画面構成

| URL | 使う人 | 端末 |
|---|---|---|
| `/tv` | お客さん全員が見る | 店内テレビ(1920×1080、横) |
| `/control` | ディーラー/スタッフ | スマホ・タブレット(縦) |
| `/admin` | 店長 | スマホ・PC |

起動時、ターミナルに3画面のURL(LANのIPアドレス付き)を表示すること。

## 3. ゲームルール

### 発動条件
- フルハウス以上でショーダウン勝ちしたとき
- プレイ・ザ・ボード(ボードだけで役が完成)は対象外 → 操作画面に注意書きを出す
- 対象ゲーム(トーナメント/キャッシュ/両方)は `/admin` で切替。初期値:両方

### 役ごとの回転数(`/admin` で変更可)
| 役 | 回転数 | 備考 |
|---|---|---|
| フルハウス | 1 | |
| フォーカード | 2 | |
| ストレートフラッシュ | 3 | |
| ロイヤルフラッシュ | 5 | 1回目は 7️⃣ 確定 |

### 回すタイミング
- その場で全回転を消化する。持ち越し・後回しは不可
- 同時に複数人が当選した場合は待機列に積み、順番に回す

## 4. リールと確率

### 初期設定(すべて `/admin` で変更可)
| ID | 絵柄 | 景品(表示名) | 確率 |
|---|---|---|---|
| miss | 💀 | ハズレ | 45% |
| drink | 🍺 | ソフトドリンク1杯 | 25% |
| point | ⭐ | ポイント | 15% |
| stack | 🪙 | 次回スタック +5000 | 10% |
| jackpot | 7️⃣ | 大当たり(次回エントリー無料) | 5% |

- 確率の合計が100%にならない設定は保存できないようにする
- 絵柄・景品名・確率・項目数を自由に追加/削除できる

### 抽選ロジック(重要)
- 結果は **サーバー側で先に決める**(重み付き抽選、`crypto.randomInt` を使用)。リールの動きは結果に合わせた演出にすぎない
- 当たり:3リールとも同じ絵柄で止める
- ハズレ:3リールが揃わない並びで止める。**ハズレで3つ揃うことは絶対にあってはならない**
- ガセリーチ:ハズレのうち一定割合(初期値30%、`/admin` で変更可)は、1・2リール目を揃えてリーチ演出 → 3リール目で外す

## 5. テレビ画面(`/tv`)の演出

- 待機中:店名ロゴ風テキスト「HIGH HAND SLOT」、確率表、直近の当選履歴(5件)、今月の 7️⃣ 獲得者
- 当選発生:画面全体に「◯◯さん フルハウス! 1回転」のような告知 → スロット画面へ
- 回転:3リールが回り、左から順に停止
- リーチ:1・2リール目が揃ったら「リーチ!」表示、3リール目がスロー回転、効果音で溜める
- 当たり:絵柄ごとに演出の格を変える。🍺 < ⭐ < 🪙 < 7️⃣
- 7️⃣:画面フラッシュ、紙吹雪、長めのファンファーレ。他より明らかに派手に
- ハズレ:ちょっと笑える「残念…」演出(暗くなりすぎない)
- 結果画面には名前・役・景品を大きく表示し、そのまま写真を撮ってSNSに載せられるレイアウトにする
- 全回転終了後、数秒で待機画面に戻る
- 画面下に小さく「景品は店内サービスに限ります。換金はできません。」を常時表示

## 6. 操作画面(`/control`)

ディーラーが片手で迷わず使えることが最優先。

1. プレイヤー名を入力(過去の名前から候補表示)
2. 役をボタンで選択(フルハウス/フォーカード/ストフラ/ロイヤル)→ 回転数が自動で決まる
3. 「登録」→ テレビに告知が出る
4. 「回す」ボタン(大きく)。お客さんにスマホを渡して押してもらう想定
5. 回転中はボタンを無効化(連打防止)
6. 待機列の表示、誤登録の取り消し(回転前のみ)

## 7. 管理画面(`/admin`)

- 簡易パスワード保護(初期値は `9high`、`/admin` から変更可)
- 確率表・景品・絵柄の編集
- 役ごとの回転数、ガセリーチ率、対象ゲームの設定
- ログ一覧(日時・名前・役・結果・景品)
- ログのCSVダウンロード
- 月別の 7️⃣ 獲得者一覧
- 「理論値チェック」:現在の設定で10万回シミュレーションし、実際の出現率を表示

## 8. データ

- `data/settings.json`:設定一式
- `data/log.json`:全回転ログ(消さない)
- `data/players.json`:名前候補
- 書き込みは一時ファイル経由で行い、途中で電源が落ちても壊れないようにする
- 初回起動時、ファイルがなければ初期値で作成

## 9. 進め方(監督AIつき自動開発)

以下のフェーズを順番に、**ユーザーに質問せず最後まで** 進める。

1. 雛形:サーバー起動、3画面の空ページ、socket.io で画面間の通信確認
2. 抽選ロジック:重み付き抽選、リール停止位置の決定、ガセリーチ。自動テストを書く
3. テレビ画面:待機・告知・回転・リーチ・当たり/ハズレ演出
4. 操作画面:登録・待機列・回すボタン・取り消し
5. 管理画面:設定編集・ログ・CSV・理論値チェック
6. 仕上げ:`README.md`(店のスタッフ向け、起動手順を画像なしでも分かるように)、全体の最終レビュー

### 各フェーズの終わりに必ずやること
- `supervisor` エージェントを呼び、そのフェーズのレビューを依頼する
- supervisor が FAIL を出したら、指摘をすべて直して再レビュー
- PASS が出るまで次のフェーズに進まない
- 同じフェーズで3回 FAIL が続いたら、残課題を `TODO.md` に書いて次に進む
- 各フェーズの PASS ごとに git コミットする

### 完了条件
- `npm test` が全部通る
- 抽選10万回で各絵柄の出現率が設定値の ±1% 以内
- ハズレで3つ揃うケースが10万回中0回
- `npm start` だけで起動し、3画面がつながる
- `/tv` が1920×1080で崩れない、`/control` がスマホ縦で崩れない
- 最後に、起動方法と3画面のURLの開き方をユーザーに日本語で短く伝える
