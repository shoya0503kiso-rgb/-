# 05. 自動シフト生成ロジック設計

「AIが案を作る → 店長が確認・修正 → 確定」の流れ（要件12）。生成は**案（DRAFT）**を作るだけで、公開は必ず管理者操作。

## 入力（3種類）

1. **従業員の希望**：日ごとに ○（出勤可、枠/時間の指定可）／×。未提出日は ×（P-19）
2. **店舗側の月次条件**：優先度・多め/少なめ・最大/最低日数・できるだけ全部・相性条件
3. **店舗運営ルール**：営業日（店休日を除く）、日ごと枠ごとの必要人数、連勤上限

## 条件の分類（要件13）

### 絶対条件（必ず守る）
| コード | 内容 |
|-------|------|
| H1 | 出勤不可日（×・未提出）に配置しない |
| H2 | 店休日に配置しない |
| H3 | 1日1人1枠まで |
| H4 | 最大勤務日数を超えない（P-22） |
| H5 | 「絶対に同じ日にしない」ペアを同じ日にしない（P-23） |
| H6 | 必要人数を満たす（※希望者が足りなければ物理的に不可能 → **不足として明示**し、店長判断に回す） |
| H7 | 枠の指定がある希望はその枠にのみ配置 |

H6 のみ「満たせない場合がある絶対条件」なので、満たせない日は**競合レポート**に「10/18 遅番 1名不足（候補者0名）」のように出し、勝手に他の絶対条件を破らない。

### 希望条件（できるだけ守る：スコアで評価）
| コード | 内容 | 重み(既定) |
|-------|------|----------|
| S1 | 最低勤務日数を満たす | 不足1日につき 50 |
| S2 | 多め/少なめ：目標日数との差 | 差1日につき 10 |
| S3 | 優先度 高/中/低 | 配置1回につき 高+6 / 中0 / 低−6 |
| S4 | できるだけ全部入れる：入れなかった○の日 | 1日につき 15 |
| S5 | 「なるべく同じ日にしない」ペア | 同日1回につき 30 |
| S6 | 連勤上限超過（「できるだけ全部入れる」の人は対象外・レポートで警告のみ） | 超過1日につき 20 |
| S7 | 勤務日数の均等化（同じ条件の人同士） | 目標との差の二乗 × 2 |

### 目標日数の決め方
- 基準 = 月の総必要人日 ÷ 希望提出者数 を、本人の ○ の日数で上限カット
- 多め：基準×1.3、少なめ：基準×0.7、できるだけ全部：○の日数
- 最大/最低が設定されていればその範囲に収める

## アルゴリズム

1. **前処理**：営業日 × 枠ごとの必要人数、各スタッフの候補日（○）を作る。候補者が必要人数に足りない枠を先に「不足」として確定。
2. **貪欲割当**：候補者の少ない（埋めにくい）枠から順に、絶対条件を満たす候補者の中で「スコア改善が最大」の人を割り当てる。
3. **局所改善**：一定回数（既定 2,000 回）、ランダムに「入れ替え（同じ枠の2人を交換）」「移動（別の候補者へ差し替え）」を試し、絶対条件を守りつつスコアが良くなれば採用。乱数シードを固定し、**同じ入力なら同じ結果**になる。
4. **レポート出力**：
   - 不足枠（日付・枠・不足人数・その日の候補者）
   - 守れなかった希望条件（例「Aさん 最低8日 → 6日（○が6日しかない）」）
   - スタッフ別の勤務日数・目標日数・○の日数

## 管理者の操作
- 生成結果はカレンダー（日×スタッフ）で表示。セルをタップして配置/解除/枠変更。
- 手動で変更した配置は `source = MANUAL`。**再生成時に手動配置を固定（残す）**して残りだけ作り直せる。
- 手動変更で絶対条件を破る場合（×の日に入れる等）は**警告を出すが許可**する（最終判断は店長）。
- 「公開」で状態を PUBLISHED にし、LINE通知。公開後の修正は「変更を通知」で差分のみ通知。

## 遅刻等の扱い（要件14）
- 月次条件画面に、前月の遅刻回数・要確認勤怠件数・勤務日数を**参考情報として表示するだけ**。
- 自動で優先度・日数を下げることはしない。店長が見て条件を入力する。

## AI補助（P-26）
- 生成はルールベース最適化（説明可能・再現可能）。
- 将来、生成AI（Claude API）で「店長メモの自然文 → 条件への変換提案」「生成結果の説明文」を追加できるよう、条件入力は構造化データで保持している。
