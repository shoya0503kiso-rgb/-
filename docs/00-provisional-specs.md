# 00. 暫定仕様一覧（店長確認待ち）

元要件で決まっていなかった項目を、監督AIが暫定で決めたもの。
**★** は業務への影響が大きく、運用開始前に必ず店長に確認したい項目。
「設定で変更可」とあるものは管理画面（店舗設定）からコード修正なしで変えられる。

| ID | 項目 | 暫定仕様 | 変更方法 |
|----|------|---------|---------|
| P-01 | 技術構成・ホスティング | Next.js + TypeScript + Prisma。開発は SQLite、本番は PostgreSQL を想定（例：Vercel + Neon/Supabase、小規模なら無料〜月数千円）。LINE Webhook のため公開HTTPSが必要 | 要相談 |
| P-02 | 店舗数 | 単一店舗前提。複数店舗化はテーブル追加で拡張できる構造にする | 将来対応 |
| P-03 | タイムゾーン | 日本時間（Asia/Tokyo）固定 | — |
| P-04 ★ | 営業日の区切り（日跨ぎ） | **日付切替時刻 = 06:00**。出勤打刻の時刻がその営業日に属する（例：10/12 20:00出勤→10/13 03:00退勤は「10/12」の勤務）。06:00より前の出勤は前日扱い | 設定で変更可 |
| P-05 ★ | 営業時間 | **15:00〜翌05:00**（異常チェックの基準にのみ使用） | 設定で変更可 |
| P-06 ★ | iPad打刻の本人確認 | iPadを管理者が「打刻端末」として登録し、端末上では**名前をタップ→ボタンを押すだけ**（2タップ）。なりすまし防止が必要なスタッフだけ4桁PINを設定可能 | スタッフごとに設定 |
| P-07 | 退勤のみの打刻 | 受け付ける（出勤時刻が空の勤怠を作り「要確認」にする）。店長が出勤時刻を補正する | — |
| P-08 | 休憩 | 1勤務に複数回取得可。休憩中に退勤した場合は退勤時刻で休憩を自動終了し「要確認」にする | — |
| P-09 ★ | 時間の計算・丸め | 実働 = 退勤 − 出勤 − 休憩合計。**1分単位・丸めなし**（給与計算上の丸めは社労士確認後に設定化） | 将来設定化 |
| P-10 | 異常判定の閾値 | 長時間：拘束12時間超／営業時間外：開店2時間前より前の出勤・閉店2時間後より後の退勤／退勤漏れ：その営業日の閉店＋2時間を過ぎても（または出勤から16時間たっても）退勤なし。この時点で打刻画面でも「未出勤」に戻り、翌日の出勤ができる（閉店から12時間以内なら、打刻画面の「退勤」でその勤怠に退勤を付けられる）／短すぎ：拘束10分未満／同じ時間帯の勤怠の二重登録は不可 | 設定で変更可 |
| P-11 | 一般的な休憩不足チェック | 労基法34条の一般基準で判定：実働6時間超→休憩45分以上、8時間超→60分以上。全日対象（最終判断は社労士確認） | 設定でON/OFF |
| P-12 ★ | 休日の休憩チェック | **休日 = 土・日・祝日（内閣府の祝日）＋店舗が個別に指定した日**。「7時間以上」は**実働時間**で判定。休日かつ実働7時間以上かつ休憩60分未満→「休憩時間を確認してください」 | 休日の曜日・指定日・時間は設定で変更可 |
| P-13 | 勤怠修正 | 管理者のみ修正可。**修正理由は必須**。修正前後の値・修正者・日時を履歴保存。削除も論理削除（履歴に残る） | — |
| P-14 | 要確認の「確認済み」 | 管理者が確認済みにすると件数から外れる（記録は残る）。その後勤怠が修正されると再判定される | — |
| P-15 | PDF出力 | 日本語フォント問題を避けるため、**印刷用ページ**をブラウザの「PDFとして保存」で出力。CSV は Excel で文字化けしないよう UTF-8(BOM付き) | — |
| P-16 | 管理者権限 | 「管理者」1種類（ID/パスワード、5回失敗で15分ロック）。店長/シフト担当の権限分けは将来対応。打刻端末を登録すると、その端末の管理者ログインは自動で解除する | 将来対応 |
| P-17 ★ | LINE連携方式 | Messaging API を使用。紐付けは管理画面で発行する**6桁の連携コードをLINEトークで送信**。シフト提出は、LINEで届く**本人専用リンク（有効期限付き）**からWeb画面で入力（LIFFは将来対応） | — |
| P-18 ★ | シフトの形 | 店舗が「シフト枠」（例：早番 15:00-23:00 / 遅番 20:00-翌5:00）を定義し、曜日ごと・日ごとに枠別の必要人数を設定。希望は日ごとに「○出勤可（枠または時間指定）／×不可」 | 設定で変更可 |
| P-19 ★ | 提出スケジュール | 13日 10:00 提出依頼通知 → 16日 10:00 未提出者へリマインド → **17日 23:59 締切** → 20日 公開。**未提出日・未提出者は「出勤不可」扱い**（店長が手動で入れることは可能） | 日付は設定で変更可 |
| P-20 | 締切後の提出 | 締切後はスタッフ側から提出・変更不可（閲覧のみ）。管理者が代理入力・締切延長できる | — |
| P-21 | 確定後の変更 | 管理者が修正→「変更を公開・通知」で、変更があったスタッフにだけLINE通知。公開前に、店休日・×の日・最大日数・絶対NGペアに反する配置を一覧表示（店長判断で公開は可能）。配置0件では公開できない | — |
| P-22 ★ | 最大/最低勤務日数 | **最大勤務日数＝絶対条件**、最低勤務日数＝希望条件（希望が少なくて満たせない場合があるため） | — |
| P-23 | 相性条件 | 「なるべく同じ日にしない（希望）」「絶対に同じ日にしない（絶対）」を選択 | 月次条件で設定 |
| P-24 | 遅刻の定義 | 確定シフト開始時刻＋5分を過ぎた出勤打刻を「遅刻」として**回数を表示するだけ**。シフトの自動減などの処遇判断はしない | 猶予分は設定で変更可 |
| P-25 | 連勤 | 希望条件として 6連勤以上を避ける | 設定で変更可 |
| P-26 | 「AI」の範囲 | シフト案は**ルールに基づく最適化ロジック**で作成（毎回同じ条件なら同じ結果、理由を説明できる）。生成AI（Claude API）は将来、条件の自然文入力補助・結果説明に使える接続口のみ用意 | — |
| P-27 | 給与目安 | 時給 × 実働 + 深夜割増（22:00〜05:00 25%）+ 時間外割増（1勤務8時間超 25%）の概算。1円未満切り捨て。交通費・週40時間超/休日の割増・控除は含まない「目安」表示。管理画面・LINE「給与目安」・本人ページで確認できる | 時給は従業員ごとに設定 |

## 店長に確認したいこと（優先順）

1. 営業時間と、日跨ぎ勤務の日付の扱い（P-04/P-05）
2. 「休日」は土日祝でよいか、店休日やスタッフ個人の休日のことか（P-12）
3. シフトは「早番/遅番」のような枠があるか、毎日バラバラの時間か（P-18）
4. 打刻は名前タップだけでよいか（P-06）
5. 一般的な休憩不足チェック（P-11）を平日にもかけてよいか（初期値ON。OFFにすると休日ルールだけになる）
6. 本番サーバーの費用感・LINE公式アカウントのプラン（無料プランは月200通まで）（P-01/P-17）
